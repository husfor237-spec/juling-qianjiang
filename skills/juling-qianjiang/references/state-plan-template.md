# 状态文件模板 · `.codex-run/state/plan.md`

这份文件的**唯一验收标准**：

> 一个从没见过这次对话的人（或一个全新的会话），只读这一份文件，能不能接着把活干完？

不能，就说明这份文件没写完。**轮换的成败全押在这里** —— 状态文件不自包含，轮换就等于丢上下文，比压缩更糟。

## 硬性要求

- **每轮结束都重写整份**，不要追加。追加会留下已被推翻的旧结论，那比没有更危险。
- **每条事实都带来源指针**（`文件:行` 或 URL）。没有指针的写进「未决项」。
- **不要把推理过程写进来。** 写判据，不写故事。推理是压缩的对象，判据是要活下来的东西。
- **未决项不能空着。** 空的未决项通常意味着你在掩盖不确定性。
- 轮次计数如实写。到了 8 轮就说明任务该拆，不要悄悄往上加。

## 模板

```markdown
# 任务状态

轮次：N / 8
更新时间：<ISO 时间>
深度：simple | general | complex

## 目标
<一句话。用户到底要什么。>

## 规格（已冻结 · 第 N 轮定稿）
- [ ] <验收标准 1>
- [ ] <验收标准 2>
- [x] <已满足的，附证据指针>

> 冻结后只允许**增加**条目，不允许删改。要改规格必须写明为什么，并说明已经做的工作哪些作废。

## 已确认事实
- <事实>（来源：<文件:行> 或 <URL>）
- ...

> 只写有来源的。没有来源的放「未决项」。

## 未决项
- <还没确认的事>（卡在哪 / 谁能确认 / 下一步怎么确认）
- ...

## 证据位置
- <产物文件绝对路径> —— <是什么>
- <命令与输出存档路径>
- <URL>

> 压缩会丢掉记忆，但丢不掉磁盘。这一节就是压缩后能重新站起来的原因。

## 派发记录
| 轮次 | 角色 | 问了什么 | 结论一句话 | 产物 |
|---|---|---|---|---|
| 1 | scout | <问题> | <结论> | recon/xxx.md |
| 3 | inspector | 审查 v1 | 2 条反对 | reviews/v1.md |

## 反驳与裁决
- 反对：<监军说了什么>
  裁决：接受 / 驳回
  依据：<实际做的验证 + 结果；驳回时这一栏必须填，否则视为接受>

## 下一步
<下一个人接手后，第一件该做的事。要具体到可执行。>

## 已知的坑
- <踩过的、别再踩的>
```

## 反面模式（都见过）

| 写法 | 为什么不行 |
|---|---|
| `## 已确认事实` 里写「应该是 X」 | 「应该」不是事实。放未决项。 |
| 未决项留空 | 掩盖不确定性，接手的人会重复踩坑 |
| 只写结论不写来源 | 压缩后无法复核，等于没有 |
| 把整段推理抄进来 | 那就不是状态文件，是聊天记录的劣质摘要 |
| 「下一步：继续优化」 | 不可执行。要写成「跑 X 命令，看 Y 是否成立」 |
| 轮次写了但没数 | 预算失效，降智无法预警 |
