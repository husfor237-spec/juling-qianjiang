# 拘灵遣将 · juling-qianjiang

一个 Codex skill：让主代理**先派子代理探路再动手**，并把它自己的上下文压到小到不会被迫压缩两次。另附两个 `read-only` 自定义代理定义。

> A Codex skill that makes the main agent delegate reconnaissance and adversarial review to subagents, and keeps its own context small enough that it never has to compact twice.

名字取自《一人之下》。这里的「将」是 Codex 的子代理。

---

## 它治什么病

「GPT 老是自己一个人做，很少派子代理，只会听命令，做得也垃圾」——这其实是**三种不同的病**，混在一起就治不好：

| 症状 | 病 | 这个 skill 能不能治 |
|---|---|---|
| 不探路就动手 | 流程病 | **能**。靠强制输出形状，不靠劝 |
| 只服从字面、不反对 | 顺从病 | **能**。靠改义务，不靠给许可 |
| 做得垃圾（推理/知识） | 能力病 | **不能**。提示词不会让模型变聪明 |

第三行是设计的前提。这个 skill 的目标不是让模型变聪明，而是**不让它把仅有的智商浪费在错的问题上，并且不让它自己给自己打分**。抱着「让 GPT 变聪明」的期待装它，一定失望。

## 工作原理

三个角色，两条不变量。

| 角色 | 谁 | 职责 | 硬边界 |
|---|---|---|---|
| **主将** | 主会话 | 立规格、派发、裁决、交付 | 只装指针，不装内容 |
| **探子** | 子代理 `scout` | 只探不谋 | `read-only`，禁止提案 |
| **监军** | 子代理 `inspector` | 只看成品，不看理由 | `read-only`，只报告 |

两条不变量，任何一步都不许破：

1. **主将不装内容。** 子代理回报给主将的只有「指针 + 精简摘要」。全文留在子代理自己的上下文里，或者按路径现取。
2. **证据永不压缩。** 压缩只能压缩推理。被引用的证据必须在压缩或轮换之前就落盘。

### 为什么主将必须薄

主将是唯一必须活到最后的角色，所以它必须是上下文最小的角色——这两句是同一个约束。

主将一旦自己揽活，上下文就随**工作量**增长，于是必然压缩，而压缩是「保留故事、丢掉判据」的不可逆操作。把噪音挡在子代理的上下文里，主将的增长就只跟**轮数**有关，与任务大小无关。

### 为什么是轮换而不是压缩

| | 压缩 | 轮换 |
|---|---|---|
| 可逆性 | 不可逆 | 可逆（证据一直在盘上） |
| 可审计 | 否，你看不出它忘了什么 | 是，状态文件是人能读的 |
| 能力 | 降智，幅度未知 | 新会话满血 |
| 前提 | 无 | **状态文件必须自包含** |

最后一行是整个设计里最要紧的地方。状态文件的唯一验收标准是：

> 一个从没见过这次对话的人，只读这一份文件，能不能接着把活干完？

不能，轮换就等于丢上下文，比压缩更糟。

另外：**轮次预算是信号，不是故障。** 主将每个任务预算 8 轮。超预算的正确含义是「任务该拆了」，而不是「该压缩了」。压缩次数 > 1 是设计失败信号。

### 为什么子代理是只读的

`sandbox_mode = "read-only"` 是**物理约束**：探子和监军改不了任何文件。这比在提示词里写一百遍「不要动手」强得多——只读的探子不会「顺手把活干了」，只读的监军不会「顺手把问题修了」，因此只能回报。

代价：只读代理不能落盘产物。所以侦察的价值被定义为「带来源指针的精简摘要」——噪音（翻文件、读日志）留在探子自己的上下文里丢掉，需要细节时按指针现取。这是刻意的取舍：**用「物理上改不了仓库」换掉「全部证据永久留档」**。

### 为什么禁止扮演子代理

如果派发不可用，模型很容易开始自己写「子代理 A 认为……」——那不是派发，那是把自己的猜测洗成第二方意见，**比不派发更糟**，因为它制造了虚假的独立性，让后面的审查全部失效。

判断标准很简单：**子代理的回报是它自己产生的，还是你写的？**

### 互审要成立，需要四个结构条件

同模型互审会自然退化（锚定、互相让步、挑刺通胀、相关盲区）。靠喊「你要严格」没用，得靠结构：

1. **信息不对称**——监军只看成品 + 规格，**绝不看主将的推理**。理由是可见的，审查就退化成「复核这套说法自不自洽」。
2. **反对必须有价**——每条反对必须写得出「什么观察能证实它」。写不出来的降级为建议。
3. **裁决靠证据，不靠第三个意见**——主将可以驳回反对，但**只能用证据驳回**。意见对意见永远不收敛，只会磨成糊。
4. **禁止自评 + 轮次上限**——两轮不收敛就停下，把未解决项显式列给用户。

## 安装

要求：Codex（桌面 app / CLI / IDE 都行），当前版本子代理默认开启。

```powershell
# 1. 装 skill 和两个子代理定义
.\install.ps1

# 2. 手动把 [agents] 段加进 ~/.codex/config.toml
#    （install.ps1 会把它打印出来，不替你改配置）
```

或者手动复制：

```text
agents/scout.toml            ->  ~/.codex/agents/scout.toml
agents/inspector.toml        ->  ~/.codex/agents/inspector.toml
skills/juling-qianjiang/     ->  ~/.codex/skills/juling-qianjiang/
```

然后开一个**新会话**（skill 列表是在会话开始时装进上下文的），发：

```text
用 $juling-qianjiang 走一遍。先派 scout 探路，回报后立规格再动手，交付前派 inspector 审一遍。
```

看三件事，它们分别证明三个机制真的活了：

1. app 里出现了 scout 的 agent thread —— 证明真派发，不是它自己扮演
2. scout 的回报只有 10 行左右且带来源指针 —— 证明「主将不装内容」生效
3. inspector 的反对带「证实」栏 —— 证明对抗性审查没退化成「看起来没问题」

如果第 1 条没出现，就是它在扮演子代理。

### 可选：`[agents]` 配置

```toml
[agents]
max_concurrent_threads_per_session = 4
default_subagent_reasoning_effort = "high"
# 想给没显式指定模型的派发省钱，可解开这行（gpt-6-luna 是快而便宜的档）：
# default_subagent_model = "gpt-6-luna"
```

`agents.enabled` 默认为 `true`，所以派发本来就可用——**缺的不是开关，是指令**，这正是这个 skill 要补的。

## 可选依赖：context-gauge

`SKILL.md` 的轮换阈值默认复用 [context-gauge](https://github.com/husfor237-spec/context-gauge) 的准确 token 数（服务端上报，不是估算）。**它不是必需的**：没有它时流程降级为「只看轮次预算」，并会如实告诉用户降级了。

## 它治不了什么

- **不会让模型变聪明。** 它治流程病和顺从病，治不了能力病。
- **同模型互审仍有相关盲区。** 同权重 = 同样的不知道。互审能救「锚定与自我合理化」，救不了「共同的无知」。后者只能靠外部证据（搜索、真跑一遍、测试）或换一个模型／换一个人。
- **它增加 token 消耗。** 每个子代理都要自己做模型和工具调用。任务是重只读（探索、测试、分类、总结）时最划算；重写入的并行要谨慎，多个代理同时改代码会冲突。
